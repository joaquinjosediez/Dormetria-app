INFORME CLINICO (Ruffa, 22-09-2026). No era el prefill: eso ya estaba
resuelto. La funcion de Supabase devuelve el JSON del modelo dentro de
`texto` cuando ella no logra parsearlo, y dmLeerEstructura exigia que el
primer caracter fuera '{'. Al fallar, el render caia al modo "parrafos"
y le mostraba el JSON crudo al profesional.

Tres cosas rompen el parseo, todas del modelo:
  1. lo envuelve en ```json ... ```
  2. antepone una linea de cortesia
  3. se queda sin tokens y corta el JSON por la mitad  <- el caso real

Ahora las tres se recuperan: se sacan los cercos, se busca de la primera
llave a la ultima, y si quedo truncado se cierran las aperturas
retrocediendo al ultimo item completo. Si corto adentro de un string
devuelve null en vez de adivinar. Si igual no se puede reparar, dice "El
informe llego incompleto", ofrece Rehacer y deja el crudo plegado.
Copiar tampoco pega un JSON en la historia clinica.

PENDIENTE del lado de Supabase: subir max_tokens de 1500 a 4000. Esto es
un paracaidas, no el arreglo de fondo.

ENCUADRE REGULATORIO (ANMAT Disp. 64/25 y guia SaMD)

- Fuera la sugerencia de farmaco. El campo decia "Solo como puente, <= 4
  semanas": eso es dirigir el cuidado clinico, no informarlo, y es una
  columna entera mas arriba en la matriz de riesgo. Queda la referencia
  de la guia (AASM 2021 / ESRS 2023).
- Banderas reescritas como cotejo contra referencia, no como deteccion.
  "Apnea probable" -> "STOP-BANG sobre el punto de corte". ANMAT nombra
  la deteccion de apnea como ejemplo de software que SI es dispositivo.
- La de somnolencia al volante ya no indica evaluar restricciones de
  conduccion: dice que conviene conversar como afecta las actividades
  que requieren atencion sostenida. Misma informacion clinica, sin
  disparar una conducta de corto plazo.
- Cada bandera muestra su umbral con la cita. Criterio 4: el usuario
  tiene que poder revisar la base de lo que ve.
- Los matices pasaron de instrucciones a lo que dicen las guias.
