# Encuestas del programa TCC-I

## Por qué

Tres momentos distintos, y no piden lo mismo:

| Momento | Qué mide | Para qué sirve |
|---|---|---|
| Antes de cada semana | Cuánto se compromete con la tarea | Predice abandono antes de que ocurra |
| Al cerrar cada semana | Si le sirvió · cuánto le costó sostenerlo | Separa lo que funciona de lo que funciona pero nadie sostiene |
| Al terminar | Balance global, recomendación, qué sacaría | Decide qué se cambia de la próxima versión |

La segunda columna es la que importa. Una semana puede tener **8 de utilidad
y 9 de costo**: eso no es una semana buena, es una semana que va a hacer que
la gente abandone en la tercera. Sin las dos preguntas juntas no lo ves.

## La tabla

```sql
-- ════════════════════════════════════════════════════════════════════
-- Dormetria · mod223 — encuestas del programa TCC-I
-- Idempotente.
-- ════════════════════════════════════════════════════════════════════

create table if not exists public.tcci_encuestas (
  id            bigint generated by default as identity primary key,
  patient_email text        not null,
  tipo          text        not null,   -- compromiso | cierre-semana | precio | final
  semana        integer,                -- null en precio y final
  respuestas    jsonb       not null default '{}'::jsonb,
  created_at    timestamptz not null default now()
);

create index if not exists tcci_encuestas_paciente_idx
  on public.tcci_encuestas (patient_email, created_at desc);
create index if not exists tcci_encuestas_tipo_idx
  on public.tcci_encuestas (tipo, semana);

alter table public.tcci_encuestas enable row level security;
```

## Las políticas

Tres, y cada una responde a una pregunta distinta.

```sql
-- 1 · La persona escribe SOLO sus propias respuestas.
drop policy if exists tcci_encuestas_insert_propio on public.tcci_encuestas;
create policy tcci_encuestas_insert_propio
  on public.tcci_encuestas for insert to authenticated
  with check (
    patient_email in (select email from public.patients where auth_id = auth.uid())
  );

-- 2 · Y lee SOLO las propias.
drop policy if exists tcci_encuestas_select_propio on public.tcci_encuestas;
create policy tcci_encuestas_select_propio
  on public.tcci_encuestas for select to authenticated
  using (
    patient_email in (select email from public.patients where auth_id = auth.uid())
  );

-- 3 · Admin lee todo: es quien necesita el agregado para decidir.
--     Se usa es_admin(), la misma función que el resto del esquema.
drop policy if exists tcci_encuestas_admin on public.tcci_encuestas;
create policy tcci_encuestas_admin
  on public.tcci_encuestas for select to authenticated
  using ( public.es_admin() );
```

> **No hay policy de UPDATE ni de DELETE, a propósito.** Una respuesta de
> encuesta no se corrige: si la persona contesta otra vez, es otra fila con
> otra fecha. Poder editarlas después destruye la serie temporal, que es lo
> único que hace útil el dato.

## Verificar

```sql
select policyname, cmd, qual, with_check
from pg_policies
where schemaname='public' and tablename='tcci_encuestas'
order by cmd, policyname;
```

Tienen que salir tres filas: un INSERT y dos SELECT.

## Para leer los resultados

Utilidad contra costo, semana por semana — que es la tabla que vas a mirar:

```sql
select
  semana,
  count(*)                                              as respuestas,
  round(avg((respuestas->>'sirvio')::numeric), 1)       as utilidad,
  round(avg((respuestas->>'costo')::numeric),  1)       as costo,
  round(avg((respuestas->>'sirvio')::numeric)
      - avg((respuestas->>'costo')::numeric),  1)       as saldo
from public.tcci_encuestas
where tipo = 'cierre-semana'
group by semana
order by semana;
```

Un **saldo negativo** marca la semana donde el programa pide más de lo que
devuelve. Es la primera candidata a reescribirse.

Compromiso previo contra si después la terminó:

```sql
select
  c.semana,
  round(avg((c.respuestas->>'compromiso')::numeric), 1) as compromiso_previo,
  count(f.id)                                           as la_terminaron,
  count(c.id)                                           as la_empezaron
from public.tcci_encuestas c
left join public.tcci_encuestas f
  on f.patient_email = c.patient_email
 and f.semana = c.semana
 and f.tipo = 'cierre-semana'
where c.tipo = 'compromiso'
group by c.semana
order by c.semana;
```

Precio:

```sql
select respuestas->>'precio' as tramo, count(*)
from public.tcci_encuestas
where tipo = 'precio'
group by 1 order by 2 desc;
```

## Mientras tanto

**El programa funciona igual sin esta tabla.** Las respuestas se guardan en
el dispositivo y el intento de subirlas falla en silencio: que una tabla no
exista no puede frenar un tratamiento a mitad de camino. Pero hasta que la
corras no vas a poder leer nada agregado.
